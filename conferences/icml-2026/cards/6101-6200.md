## 6101 · Proxy Compression for Language Modeling

[原文](https://proceedings.mlr.press/v306/zheng26e.html)

<a id="zheng26e-training-strategies"></a>

**技术主题** · 压缩视图训练与原始字节推理

- **问题 / 瓶颈** · byte序列长拖累训练，固定tokenizer又绑定接口；压缩算法结构不同，transfer未必成立。
- **核心创新 / 方法** · Bernoulli抽raw/comp view，以同一next-symbol objective训共享LM，warmup时random order配对；tokenizer IDs或神经arithmetic-coded symbols作proxy，可离线entropy分段并行压缩；inference移除compressor。
- **Baseline** · byte LM/EvaByte、mixed representation/domain transfer与external compression为来源；实际pure-byte/BPE/neural/tokenizer/gzip及ratio/pairing ablation。暂定增量为proxy-only训练提速却raw-only推理接口和compressor failure boundary，最近原作待核。
- **Benchmark** · RefineCode GitHub约3.3TB，EvaByte .5–14B，每model100B symbols≈matchedtrainingFLOPs，另1.5/7B320Bsymbols；HumanEval+/MBPP+ pass1、BPB、压缩稳定度与oracle translation单列。
- **关键结果 / 消融** · 14B100Bsymbol MBPP+ proxytoken49.5/neural49.2对byte42.1/token48.1；.5B neural22.0劣byte25.9。320B 7B neuralHumanEval21.3等token、byte14.6；gzip混合始终劣purebyte，非任意lossless compressor有效。
- **适用条件 / 局限** · same symbols/compute不等same raw bytes，更多内容暴露本就是机制，需计proxy预处理/小compressor训练/存储。raw inference仍长序列非等latency；oracle compressed solution translation不等无答案code generation，神经压缩元数据/可逆性与多语言非代码泛化待核。

## 6102 · Image Restoration via Diffusion Models with Dynamic Resolution

[原文](https://proceedings.mlr.press/v306/zheng26f.html)

<a id="zheng26f-inference"></a>

**技术主题** · 动态子空间恢复的测量校正与晚期去噪

- **问题 / 瓶颈** · 全像素posterior采样昂贵，latent VAE反复编解码又有开销，简单多分辨率迁移可能丢data consistency。
- **核心创新 / 方法** · 先fine-tune dynamicresolution prior；SubDAPS在当前subspace解r||x−xprior||²+||y−A(Ux)||²；++用CG替Langevin修正，若correction<τ且过最后upsample则DDIM式确定更新，末尾replay储存clean estimates做高阶corrector。
- **Baseline** · SubspaceDM/Jing2022、DPS/DAPS、deterministic sampler及CG/data-consistency为来源；实际pixel/latent DPS/DAPS、DiffPIR/MGPS/AdaPS与Sub变体。暂定增量为resolution+measurement条件的switch/corrector，最近原作待核。
- **Benchmark** · FFHQ/ImageNet256²各100validationimages，四linear两nonlinear恢复，Gaussian measurement σ=.05；PSNR/SSIM/LPIPS/FID、运行时/NFE；noise/upsample日程与prior fine-tune总成本待核。
- **关键结果 / 消融** · FFHQ4xSR SubDAPS++ PSNR29.34对DAPS28.88，但LPIPS .157劣AdaPS .090；ImageNet random70%inpaint28.61低DiffPIR28.70，FID49.15劣48.71。SubDPS多数低于DPS，不能称dynamic resolution本身保证提升。
- **适用条件 / 局限** · subspace缩小会丢超出当前range的信息，projection/noise/cutoff近似不保正确posterior sampling；nonlinear A下CG与线性CG保证不同。零额外NFE不等零算量/显存，100图FID方差及per-task调参、先验适配预算待核。

## 6105 · UniCode: Augmenting Evaluation for Code Reasoning

[原文](https://proceedings.mlr.press/v306/zheng26i.html)

<a id="zheng26i-evaluation"></a>

**技术主题** · 区分叙述变化与算法结构变化的代码测试

- **问题 / 瓶颈** · 静态code pass可被模板匹配高估，改变结构后仍沿原算法可能通过弱测试。
- **核心创新 / 方法** · LLM生成atomic/compositional variants；small brute force过滤optimized参考解、large inputs多数共识，分歧用judge仲裁；按augmentation轴及stress test类型报告pass、错误回归seed逻辑。
- **Baseline** · metamorphic/differential testing、code augmentation和benchmark contamination分析为来源；实际多reasoning/nonreasoning LLM、TestEval校验tests。暂定独立增量是结构变体下seed-regression的有界失败剖面，生成pipeline本身非新，最近原作待核。
- **Benchmark** · UniCode由seed算法题生成narrative/rule/efficiency/sequential/concept变体，多difficulty；pass1、各测试子集影响与cost，TestEval test correctness/coverage；对代码RL/demo筛选的用途是增加结构变化评测，非原文新训练算法。
- **关键结果 / 消融** · o4mini narrative92.5%、rule86.4%、efficiency55.6%、sequential73.3%、concept68.2；deepseekR1 narrative94%、sequence53.3%，差异大。test pipeline作者94.5%correct/86%coverage，非完美oracle，不能将所有新失败都当模型真实错误。
- **适用条件 / 局限** · 结构变体也改变题难/解长/计算预算，非单独证明memorization因果；LLM生成题/解/test同源错误可相关，多数票不认证真值。31.2%摘要drop的汇总口径待核；seed-regression人工/自动判定、同difficulty/token预算和去重复边界待核。

## 6107 · LEAP: Zone-Aware MCTS for LLM Self-Speculative Decoding

[原文](https://proceedings.mlr.press/v306/zheng26k.html)

<a id="zheng26k-inference"></a>

**技术主题** · prefill冗余分区的自推测层搜索

- **问题 / 瓶颈** · 全layer mask搜索空间大，在线反复改draft可能亏损，prefill统计能否迁到decode关键。
- **核心创新 / 方法** · early仅execute、middle execute/skip、final execute/repeat；按冗余分组做MCTS，以实测accept length/latency reward更新，最优配置多轮不变后fix；复用target KV、树draft及标准lossless rejection verification。
- **Baseline** · layer-skipping selfdraft、MCTS与SWIFT/CLaSP为来源；实际比较二者、去zone/group/search组件。暂定增量为prefill→decode冗余稳定的经验边界及zone-constrained在线group搜索，最近原作待核。
- **Benchmark** · Llama3 8/70B，GSM8K/MTBench/CNN-DM/NQ/WMT14，batch1、max1024generated、temperature0/1；walltime speedup、meanaccepted/generated length、layer redundancy Spearman；短prefill/不同batch待核。
- **关键结果 / 消融** · 8B temp0 overall2.05x对CLaSP1.27，70B1.94x对1.52；temp1 8B1.68x、70B1.73x。去group speed1.63x。feature redundancy prefill/decode相关约>.96，acceptance增益相关约.7，不能当每层收益精确预测。
- **适用条件 / 局限** · MCTS convergence heuristic不认证最优mask或开销可忽略，若prompt短/输出短可能亏；repeat在文中组(A,B)写作(A,A,B,B)而非整个AB两遍，需按实现核。standard verifier才决定lossless，skip/repeat的cache一致性与float、搜索成本是否含计时待核。

## 6109 · HilbertA: Hilbert-Curve–Aligned Sparse Attention for 2D Structured Data

[原文](https://proceedings.mlr.press/v306/zheng26m.html)

<a id="zheng26m-inference"></a>

**技术主题** · Hilbert序的连续块稀疏与层间滑动

- **问题 / 瓶颈** · 二维局部稀疏mask常导致不规则memory access，计算量降但GPU不一定加速。
- **核心创新 / 方法** · 图像tokens Hilbert ordering、contiguous tile attention，层间shift NT/L索引而不搬内存，central shared region和prompt共用信息通路；GPUkernel融合index访问与局部attention。
- **Baseline** · space-filling curves、Swin shifted windows与IO-aware sparseattention为来源；实际对比serpentine/Morton/Moore/spiral、SpargeAttention/CLEAR和去sliding/shared区域。暂定增量为Hilbert layout+滑动/共享核执行接口，最近原作待核。
- **Benchmark** · Flux1 dev1024²/2048²35steps、Flux2Klein9B1024²10steps，Qwen3VL8B InfoVQA/SEED/MMBench/OCRBench/MMStar；singleA100 medianlatency、FID对COCO17K，LPIPS/CLIPI对dense outputs；diffusion轻量finetune、VLM无需额外训练。
- **关键结果 / 消融** · Flux1 2048²16tiles attention4.16x、E2E1.44x，但FID47.5劣dense32.6/4tiles38.4；Flux2 16tiles FID25.67对dense26.39、E2E仅1.07x。quality/效率tradeoff显著，不是无损稀疏。
- **适用条件 / 局限** · Hilbert locality非2D所有邻居1D邻近，GDE仅proxy且不能保geometry等距。文中ERF每layer整tile增长需sliding方向/查询窗口实际覆盖核查，不自动按公式保证全局通信；finetune和reorder开销、image/text/posID一致性、sparsity匹配待核。

## 6110 · Overcoming the Modality Gap in Context-Aided Forecasting

[原文](https://proceedings.mlr.press/v306/zheng26n.html)

<a id="zheng26n-evaluation"></a>

**技术主题** · 用无上下文与错配对照验证预测context

- **问题 / 瓶颈** · 看似相关文本可能不带history之外信息，所谓modality gap会混入context无效与backbone弱。
- **核心创新 / 方法** · 将real series window和metadata转scenario文本，生成过程可见future；先语义有效性检查，test再以强CAF的with/without提升筛选；比较接受/拒绝及swappedcontext，训练dual-attention DoubleCast主要作data验证载体。
- **Baseline** · synthetic contextual augmentation、causal ablation和prediction-based filtering为来源；实际Chronos/TimeLLM/ChatTime/DirectPrompt多LLM、DoubleCast。暂定增量为context有用性条件与跨model控制证据，新增架构非核心，最近原作待核。
- **Benchmark** · CAF7M约7.43M train/904test，65source sets40train25test；EASY/HARD/ALL、CRPS/WinRate，外部TimeMMD；test用GPT5.2 selector，训练7M因成本并非全部forecaster-filtered；数值+文本同一窗口对照。
- **关键结果 / 消融** · ALL DoubleCastCRPS .231对Chronos .278，removecontext +18.3%、swap+26.5%；GPT5.2 direct .217更好且参与筛test。TimeLLM CAF .501，removecontext反改善8%，说明同数据并不保证利用context；模型/数据条件应分开。
- **适用条件 / 局限** · 生成文本看future是受控额外信息，不能称凭history无泄漏提升或真实未来可用；selector提升筛选按结果构test，跨model相关降低但不消除偏置。train多数未forecaster筛，不能把7M全称验证有效；相关性/mean CRPS非每instance必有用，真实context可靠性/成本待核。

## 6111 · Mosaic: Unlocking Over 30$\times$ Context Length for Diffusion LLMs Inference via Global Memory Planning and Dynamic Peak Taming

[原文](https://proceedings.mlr.press/v306/zheng26o.html)

<a id="zheng26o-inference"></a>

**技术主题** · 扩散LM的mask logits与动态峰值工作区

- **问题 / 瓶颈** · 全序列反复denoise使瞬时logits/FFN activations比KV更限制显存，局部allocator复用看不到全局peak。
- **核心创新 / 方法** · mask-only fused logit kernel跳未mask positions；注册graph templates、模拟当前mask数下peak，按瓶颈逐增logit/FFN chunks；全graph first-fit tensor offset、单workspace virtual地址映射，跨graphbreak复用。
- **Baseline** · mask-aware projection、activation chunking、global lifetime planning与CUDA VMM为来源；实际officialPyNative、vLLM-portTorch、torchcompile及bruteforce/ILP/fixedchunk消融。暂定增量为dLLM mask动态峰值与全局工作区的联合规划，最近系统先例待核。
- **Benchmark** · LLaDA/Dream/LLaDA-MoE，RTX309024GB/A10040GB，prompt/total比.1/.5/.9；Lmax OOM阈值、平均perstep/总latency、peak/average与planning/search costs，质量/输出一致测试范围待核。
- **关键结果 / 消融** · 平均Lmax相对PyNative32.34x、portTorch25.41x、compile15.30x，peak/average约−2.71x；不是单一相对基线全部30x。作者E2Elatency降低2.5–55.4%，短context search/plan成本亦有消融，不将每步latency与requesttotal混同。
- **适用条件 / 局限** · 只有sampler只用masked logits时可精确省去其他行，remasking/全序列confidence策略需保所需logits。数学同算子不保证所有dtype/kernel bitwise，输出exact范围待核；若attention或其他非chunkable组件成峰会返回failure，长context compute/页映射/离线template成本仍存在。
