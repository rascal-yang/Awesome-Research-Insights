## 3801 · ScoreMix: Synthetic Data Generation by Score Composition in Diffusion Models Improves Recognition

[原文](https://proceedings.mlr.press/v306/rahimi26a.html)

<a id="rahimi26a-data-strategies"></a>

**技术主题** · 按识别特征距离选择扩散混合类别

- **问题 / 瓶颈** · 只有本域数据时，如何用类条件扩散合成对识别训练有帮助的困难样本？
- **核心创新 / 方法** · ScoreMix 在每步反向扩散凸组合两类条件分数，以混合分数推进采样。使用识别器特征空间度量类间距离，选择混合类对并加入训练。
- **Baseline** · 改进来源为扩散分数合成及本域合成增广。实验对照为只用真图、AugGen、随机选类和按生成器条件或识别特征的远近选类。
- **Benchmark** · 用 WebFace160K 训练生成与识别模型，八个公开人脸基准衡量验证 TAR 和 TinyFace rank-1 等。另评 ImageNet-1K 下的软标签训练。
- **关键结果 / 消融** · 表 1 中 IJB-C 在 FPR=10⁻⁶ 时，ScoreMix TAR 为 76.45%，只用 WebFace160K 为 70.37%，AugGen 为 75.02%。表 3 固定算力的远类特征混合平均 67.44，近类为 64.92。
- **适用条件 / 局限** · 混合采样成本更高，生成器需要在域内训练。生成条件空间与识别器空间缺少稳定距离对应，选类效果需用下游模型测。

**可复用机制** · 合成类别之间的训练样本时，可沿逆扩散逐步混合条件分数，并用当前识别器的类原型选取待混合的类对。固定合成数量与采样开销做远、近、随机对照，能直接检验哪些类间样本更有训练价值。

## 3802 · VeriSimpl: Robust Optimization Modeling from Natural Language using Simplification-based Verification

[原文](https://proceedings.mlr.press/v306/rahman26a.html)

<a id="rahman26a-inference"></a>

**技术主题** · 由求解器构造优化模型局部反例

- **问题 / 瓶颈** · 自然语言自动生成的优化程序能够执行时，怎样检验其制约条件和变量是否仍表达了原题？
- **核心创新 / 方法** · VeriSimpl 采样候选优化模型，通过求解器生成单个约束的有效、临界、违例构造和固定部分变量的局部定值问题。LLM 对照原题回答，以语义得分排序，类型验证用于破同分。
- **Baseline** · 改进来源为求解器反馈与候选模型语义验证。实验对照包括 BaseLLM、SelfDebug、OptiMUS、COE 及不同验证信号消融。
- **Benchmark** · 用 GPT-4o 和 R1 在 NL4Opt、NLP4LP、CompOR、IndOR 测端到端准确率，并检查全验证通过样本的精度和覆盖。
- **关键结果 / 消融** · GPT-4o 平均准确率为 65.5%，基础模型 56.6%，SelfDebug 59.1%。R1 为 72.8% 对基础 62.5%。GPT-4o 全验证信号平均精度 91.5%，覆盖正确样本的 34.2%。
- **适用条件 / 局限** · 验证只能检查成功构造且 LLM 能正确判断的局部情形。依赖多次求解与查询，加严全通过会降低覆盖率。

**原文定位** · [算法总览（PDF 第 4 页）](https://raw.githubusercontent.com/mlresearch/v306/main/assets/rahman26a/rahman26a.pdf#page=4) · [算法 2–3（PDF 第 5 页）](https://raw.githubusercontent.com/mlresearch/v306/main/assets/rahman26a/rahman26a.pdf#page=5) · [表 1–2（PDF 第 6 页）](https://raw.githubusercontent.com/mlresearch/v306/main/assets/rahman26a/rahman26a.pdf#page=6) · [表 4 与消融（PDF 第 7 页）](https://raw.githubusercontent.com/mlresearch/v306/main/assets/rahman26a/rahman26a.pdf#page=7) · [结论（PDF 第 9 页）](https://raw.githubusercontent.com/mlresearch/v306/main/assets/rahman26a/rahman26a.pdf#page=9)

**可复用机制** · 检查从自然语言生成的优化模型时，可固定其他条件，让求解器分别生成某条约束的边界内、边界上和边界外取值。交给语言模型根据原题独立判定这些取值，能发现程序正常运行时仍隐藏的语义错误。

## 3803 · STT-LLM: Structural-Temporal Tokenization for Adapting LLMs to Longitudinal Clinical Profiles

[原文](https://proceedings.mlr.press/v306/rahman26b.html)

<a id="rahman26b-representation-learning"></a>

**技术主题** · 把代谢关系和采样时间写入 token

- **问题 / 瓶颈** · 临床纵向数据中的稀疏采样和代谢特征依赖，在把数值直接序列化成普通文本时容易丢失。
- **核心创新 / 方法** · STT-LLM 用代谢关系图的 Laplacian 特征与带位置的时间注意力生成表征，再分别做结构和时间 token 化；冻结主模型并联合训练 tokenizer 与 LoRA。
- **Baseline** · 改进来源：LLM 原生 tokenizer 对纵向表格的文本序列化。实验对照：Qwen2.5、Falcon-3、Mistral、Llama 等原生分词，ARIMA、图时序模型和非 LLM 异常检测器。
- **Benchmark** · Steroid-M/F 及各自两次采样子集，六种尿液代谢物；测单步预测 RMSE、MAE、MAPE 与局部或全局异常的灵敏度、F1、AUC 等。
- **关键结果 / 消融** · 零样本全局异常检测，Steroid-M/F 的 F1 是 0.26/0.29，AUC 是 0.57/0.59；Steroid-M 的局部灵敏度为 15.0%，多数原生分词基线接近零。
- **适用条件 / 局限** · 证据来自运动员类固醇档案；局部异常的绝对灵敏度仍低，多步预测未报告。

**可复用机制** · 接入语言模型的纵向档案可以分开编码特征关系和采样序列，再投到模型的嵌入空间。对于少见异常，同时看灵敏度和区分度能发现总体准确率掩盖的漏检。

## 3804 · Accuracy-First Rényi Differential Privacy and Post-Processing Immunity

[原文](https://proceedings.mlr.press/v306/raisa26a.html)

<a id="raisa26a-theory-statistics"></a>

**技术主题** · 把停止时的隐私开销作为机制输出

- **问题 / 瓶颈** · 希望在私有验证集达到目标准确率后停止消耗隐私预算，而输出依数据而变的预算也必须纳入隐私保证。
- **核心创新 / 方法** · 定义 α 阶事后 Rényi DP，将随机 ε 放入对联合输出的 Rényi 型期望；证明后处理免疫与自适应组合，并给出 Brownian 机制和独立私有验证集上的停止规则。
- **Baseline** · 改进来源：纯、概率型与近似事后隐私及既有 Brownian 隐私界。实验对照：Adult 上的高斯阈值检查与稀疏向量技术 SVT；微调用公有或私有验证集。
- **Benchmark** · Adult 合成数据从七个 ε 档逐步放宽，报告梯度提升分类器的验证准确率和 ε，重复 50 次；另测 CIFAR-10 小样本分类器末层微调。
- **关键结果 / 消融** · 定理4.2证明后处理仍满足定义，推论5.3证明 Brownian 机制满足该定义。Adult 上高斯检查一般给出较高准确率，SVT 一般耗费更小的 ε。
- **适用条件 / 局限** · 私有阈值检查本身带噪，接受不保证真实验证精度一定达标；定理4.6要求训练与验证分离，微调未计超参数搜索的隐私成本。

**可复用机制** · 按精度逐步放宽预算时，要把本次选择的 ε 与数据产品一起纳入隐私分析。用独立私有验证集做阈值检查，并为停止信号记账，可为自适应流程保留后处理免疫。

## 3805 · Revisiting OOD Generalization in Programmatic RL

[原文](https://proceedings.mlr.press/v306/rajabpour26a.html)

<a id="rajabpour26a-evaluation"></a>

**技术主题** · 复核策略泛化时控制奖励和观察

- **问题 / 瓶颈** · 程序策略与神经策略的 OOD 差距可能来自奖励、观测和搜索设定，需拆开这些干扰因素。
- **核心创新 / 方法** · 在 TORCS 降低训练奖励的速度权重，在 Karel 给前馈 PPO 局部观察及上一动作，在 Parking 并报逐回合成功率和每种子全通过比例。
- **Baseline** · 改进来源：NDPS、LEAPS、PSM 的原 OOD 比较。实验对照：对应程序策略、原奖励 DDPG、卷积或 LSTM PPO，以及改观测的 PPO 和 DQN。
- **Benchmark** · TORCS 新赛道圈速与撞车，Karel 从 8×8 或 12×12 外推至 100×100 的平均回报，Parking 更窄车位在每种子 100 初态的两类成功率。
- **关键结果 / 消融** · Karel 的 100×100 TOPOFF，带上一动作的 PPO 回报 1.00，LEAPS 0.21。Parking 测试逐回合 DQN/PSM 是 0.18/0.16，但全通过比例是 0/0.06。
- **适用条件 / 局限** · 结论针对三组基准与所用 DSL；Parking 两种指标排序不同，神经策略与程序策略均有困难。

**可复用机制** · 判断程序或神经表示的跨环境泛化时，可先控制优化所用奖励和可见信息。若局部障碍就足以决定动作，限制观察并提供上一步动作可能比让高容量模型看到整个训练地图更容易学出可迁移规则。

## 3806 · Personalized Image Generation via Human-in-the-loop Bayesian Optimization

[原文](https://proceedings.mlr.press/v306/rajagopalan26a.html)

<a id="rajagopalan26a-inference"></a>

**技术主题** · 以多图选择引导注意力变形

- **问题 / 瓶颈** · 用户能看出哪张图更接近心中目标，但精确改动往往难以用提示词表达。
- **核心创新 / 方法** · MultiBO 每轮让用户从多张候选图选一张或多张，以多选偏好高斯过程和子空间采集函数选下一批；用仿射及薄板样条变换扩散自注意力 Q/K/V。
- **Baseline** · 改进来源：成对偏好贝叶斯优化与文本导向图像偏好优化。实验对照：DiffusionDPO、IterComp、DNO、DAS、DEMON，以及外部打分和成对子版本。
- **Benchmark** · T2ICompBench、HPSv2、PartiPrompts 等提示和目标图；测 CLIP-I2I、LPIPS、图像偏好分和 30 位志愿者的胜率与平均排名。
- **关键结果 / 消融** · 人工评估中 MultiBO 胜率 70.82%、平均排名 1.31，LPIPS 引导的 MultiBO 为 31.81%、2.36；DEMON 人选模式为 15.60%、2.67。
- **适用条件 / 局限** · 需多次用户反馈；注意力变形适合已有对象的形状或位置，初始图漏掉目标物体时难补全。

## 3807 · Panini: Continual Learning in Token Space via Structured Memory

[原文](https://proceedings.mlr.press/v306/rajesh26a.html)

<a id="rajesh26a-inference"></a>

**技术主题** · 把反复推理前移到文档写入

- **问题 / 瓶颈** · 固定语言模型被反复问到新文档时，原文分块检索会重复推理，也容易把无关内容塞给生成器。
- **核心创新 / 方法** · Panini 在写入时抽取实体和事件关联的问答工作区并增量合并；查询时分解子问题，沿实体关系找短证据链，只把链作为回答上下文。
- **Baseline** · 改进来源：检索原始分块的 RAG、图检索与代理式多跳搜索。实验对照：BM25、Qwen3 检索、RAPTOR、GraphRAG、HippoRAG 2、IRCoT、Search-R1。
- **Benchmark** · NQ、PopQA、MuSiQue、2Wiki、HotpotQA、LV-Eval；测 QA F1 和回答模型读入的上下文 token，另以删证据的 Platinum 子集测试弃答。
- **关键结果 / 消融** · 六项平均 F1 56.1、320 个上下文 token；HippoRAG 2 为 53.3、705。GPT-4o-mini 的 Platinum 平均无答案识别为 72.8%，HippoRAG 2 为 58.5%。
- **适用条件 / 局限** · 结构化抽取增加写入成本，小模型抽取更不稳定；尚未处理反复跨文档推理的缓存或明确知识冲突。

**原文定位** · [§2.1–2.2 结构记忆和推断链（PDF 第 3 页）](https://raw.githubusercontent.com/mlresearch/v306/main/assets/rajesh26a/rajesh26a.pdf#page=3) · [图2 查询流程（PDF 第 4 页）](https://raw.githubusercontent.com/mlresearch/v306/main/assets/rajesh26a/rajesh26a.pdf#page=4) · [§3.2–3.3 弃答与 token（PDF 第 6 页）](https://raw.githubusercontent.com/mlresearch/v306/main/assets/rajesh26a/rajesh26a.pdf#page=6) · [表2–3 结果（PDF 第 8 页）](https://raw.githubusercontent.com/mlresearch/v306/main/assets/rajesh26a/rajesh26a.pdf#page=8) · [§6 局限（PDF 第 9 页）](https://raw.githubusercontent.com/mlresearch/v306/main/assets/rajesh26a/rajesh26a.pdf#page=9)

**可复用机制** · 长期使用的文档可在写入时抽取实体相连的问答，而查询时沿实体接续子问题，只把短证据链交给回答模型。除了答对率，用缺证题的正确弃答与上下文 token 检查这项取舍。

## 3808 · MedMosaic: A Challenging Large Scale Benchmark of Diverse Medical Audio

[原文](https://proceedings.mlr.press/v306/rajgarhia26a.html)

<a id="rajgarhia26a-evaluation"></a>

**技术主题** · 分开评估听音和读问的医疗线索

- **问题 / 瓶颈** · 医疗音频评测需要区分从生理声音推断、结合语音解释线索及在长对话中整合信息的能力。
- **核心创新 / 方法** · MedMosaic 从心音、肺音、咳嗽、语音和长短对话构造选择、开放和多轮问答，含合成音色；两名专业人员分层抽检 145 对。
- **Baseline** · 改进来源：通用音频问答和单任务医疗音频评测。实验对照：Gemini-2.5-Pro/Flash、GPT-4o-Audio、Audio Flamingo 3、Phi-4-MM 等 13 个模型。
- **Benchmark** · 46,701 对问答；涵盖 CoughVID、Circor、Primock 等，结构化题测正确率、开放题用模型裁判，按类别样本数加权汇总。
